# 国試の解説

取り込み時点の国試には解説が無く、「詳しい解説は準備中です」という
プレースホルダが入っていた（第114〜119回の1153問、あとから足した
第106〜113回の1966問）。ここはその中身を書き足すための置き場。
第106〜113回は1933問に解説を書き、33問を除外した（下の「除外」）。

## ファイルの持ち方

回ごとに `106.json` … `119.json`。キーは `blueprint_code`（"114-A-1"）で、
国試データ側と 1:1 に対応する（回の中で一意であることを組み立て時に確かめる）。

```json
{
  "114-A-1": {
    "point": "正答の根拠と、この設問で問われている知識。",
    "distractors": {
      "A": "なぜ誤りか。",
      "B": "なぜ誤りか。"
    }
  }
}
```

書くのは `point` と誤答の理由だけでよい。「正答は D「…」。」の行、出典表記、
断り書きは `build_kokushi_explanations.py` が設問データから機械的に付ける。
正答の記号や選択肢の文言を手で書き写すと、データとずれたときに気づけない。

分野を直すときは `"category": "公衆衛生"` を足す。取り込み時の本文の語による
振り分け（肝・胆・膵、泌尿器、感染症など）に上書きされる分野は、組み立て時に
「取り込み時に「…」へ移される」と報告されるので、その項目は外す。

## 除外

今の知見や制度では正答が一つに決まらない設問、正答が誤りになった設問、図が
本文に入らず解けない設問は、解説の代わりに理由を書いて除外する。

```json
{
  "111-E-9": {
    "exclude": "日本透析医学会の統計では、慢性透析患者の死因は近年、感染症が第1位になっている（…）。"
  }
}
```

`--write` で設問データから外れ、`scripts/import_kokushi.py` も同じ項目を読んで
取り込み直したときに戻さない。本番に入っている回（第114〜119回）は除外できない
（公開中の設問を黙って消さないため）。

## 反映

```
python scripts/build_kokushi_explanations.py            # 組み立て + 検証
python backend/manage.py apply_kokushi_explanations     # ローカルDBへ
python scripts/build_kokushi_explanations.py --sql out.sql   # 本番用SQL
```

## 監修について

ここに書かれた解説はアプリ側で作成したもので、厚生労働省が公表している
過去問には含まれない。出典表記（Public Data License 1.0）が及ぶのは設問文と
選択肢だけなので、解説を出典の中に混ぜて表示してはいけない。組み立て側で
別段落に分け、アプリ作成であることを明記している。

医学的な監修は未了。監修が済んだものから `"reviewed": true` を付けていく。
